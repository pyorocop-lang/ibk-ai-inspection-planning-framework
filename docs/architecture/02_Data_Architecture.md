# 데이터 아키텍처 (Data Architecture)

> **공통 원칙:** AI는 검사부문을 결정하지 않고 **근거와 함께 추천**만 하며, 최종 결정은 **검사협의회(Inspection Committee)** 가 수행한다.

## 1. Purpose (목적)
검사기획에 필요한 데이터의 수집·정제·정규화·관리 구조를 정의한다.

## 2. Scope (범위)
정량·정성 데이터의 수집 소스, 품질 기준, 정규화 스키마, 보존 정책.

## 3. Input (입력)
감독·검사 기록, 건전성·민원·사고 지표, 규정·시장 데이터.

## 4. Process (처리)
수집 → 검증 → 정제 → 정규화 → 적재 단계로 처리한다.

| 단계 | 내용 |
|------|------|
| 수집 | 내·외부 소스에서 원천 데이터 취득 |
| 검증 | 결측·이상치·중복 점검 |
| 정제 | 표준 단위·코드 변환 |
| 정규화 | 검사 유니버스 ID 기준 정렬 |
| 적재 | 추론 엔진이 소비 가능한 형태로 저장 |

## 5. Output (출력)
정규화된 데이터셋과 데이터 품질 리포트.

## 6. Explainability Requirement (설명가능성 요건)
산출물은 근거·신뢰도·반론을 포함하여 사람이 이해·검증·재현할 수 있어야 한다. 모든 핵심 주장에는 출처를 표기한다.

## 7. Human Review (사람의 검증)
산출물은 1차 검토자의 근거·편향 점검을 거치며, 최종 결정은 검사협의회가 수행한다.

## 8. Example (예시)
민원 데이터 원천 → 부문 코드 매핑 → 월별 정규화 → Reasoning Engine 입력.

## 9. File Owner (문서 소유자)
검사기획 AI 운영 담당 (Inspection Planning AI Steward)
