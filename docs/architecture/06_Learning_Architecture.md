# 학습 아키텍처 (Learning & Feedback Architecture)

> **공통 원칙:** AI는 검사부문을 결정하지 않고 **근거와 함께 추천**만 하며, 최종 결정은 **검사협의회(Inspection Committee)** 가 수행한다.

## 1. Purpose (목적)
검사 결과를 지식·추론·가중치로 환류하는 지속학습 구조를 정의한다.

## 2. Scope (범위)
피드백 수집, 성과 평가(적중/오탐/누락), 모델·가중치 보정, 변경 이력.

## 3. Input (입력)
검사 실행 결과, 추천 대비 실제 결과, 신규 사례.

## 4. Process (처리)
결과 수집 → 성과 평가 → 보정안 도출 → 사람 승인 → 반영 → 기록.

| 지표 | 의미 |
|------|------|
| 적중(Hit) | 추천 부문에서 실제 문제 발견 |
| 오탐(FP) | 추천했으나 문제 없음 |
| 누락(Miss) | 미추천 부문에서 문제 발생 |

## 5. Output (출력)
보정된 가중치·키워드·매핑과 학습 변경 이력.

## 6. Explainability Requirement (설명가능성 요건)
산출물은 근거·신뢰도·반론을 포함하여 사람이 이해·검증·재현할 수 있어야 한다. 모든 핵심 주장에는 출처를 표기한다.

## 7. Human Review (사람의 검증)
산출물은 1차 검토자의 근거·편향 점검을 거치며, 최종 결정은 검사협의회가 수행한다.

## 8. Example (예시)
오탐 누적 부문의 가중치 하향(사람 승인 후) → `models/learning/` 기록.

## 9. File Owner (문서 소유자)
검사기획 AI 운영 담당 (Inspection Planning AI Steward)
